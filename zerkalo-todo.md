# Zerkalo — Multi-File Project Feature Plan

Branch: `feature/multi-file-projects`
Merge target: `main` when all must-haves are done and single-file workflow is unaffected.

---

## Background

Zerkalo is built around a single work folder treated as a file dump. Most of the
infrastructure for multi-file projects is already in place (ProjectModel parses
`#include`/`#import` graphs, auto-detects the root file, stores a root override in
`.zerkalo/config.toml`, and the compiler already takes a root path + in-memory
buffer snapshots). What is missing is the UI layer to set up, navigate, and
configure multi-file projects.

Primary use case driving this work: a theological journal with a `main.typ` that
`#include`s per-chapter files, a bibliography, and a title page.

---

## Items

### 1. New Project Wizard + Folder Creation

Create a "New Project" dialog (accessible from the header/menu). The wizard:
- Asks for a project name and template choice
- Creates `<work_dir>/<project-name>/` (slugified, no spaces)
- Generates starter files from the selected template (see §5 for templates)
- Writes a minimal `.zerkalo/config.toml` into the new folder with `root_file` set
- Opens the new project in Zerkalo (sets `project_root` to the new folder)

Files to touch: `ui/app_window.rs`, new `ui/new_project_dialog.rs`,
`project_model.rs`, `config.rs`.

---

### 2. Root File Indicator + Right-Click "Set as Compilation Root"

The file tree currently has no indication of which file is being compiled.

- Add a ★ (or bold/accent styling) to the file tree row that matches the current
  compilation root
- Right-click context menu on any file row: add "Set as Compilation Root"
- Selecting it writes `root_file` to the project's `.zerkalo/config.toml` and
  triggers a recompile

Files to touch: `ui/file_tree.rs`, `config.rs`, wiring in `ui/app_window.rs`.

---

### 3. Status Bar Root Chip

The status bar currently has no indication of what file is being compiled.

- Add a small chip/label to the status bar showing "Root: filename.typ"
- Clicking it opens a popover listing all candidate roots (files not included by
  any other) so the user can switch without going to the file tree
- Updates live when the root changes

Files to touch: `ui/editor_pane.rs` (status bar area), `ui/app_window.rs` (wiring).

---

### 4. Folder-Aware File Tree

The file tree is currently a flat list with directory headers. When projects each
live in their own folder, this doesn't reflect the structure well.

- Show files grouped under collapsible directory rows
- Files in the project root shown at top level; subdirectory files nested under
  an expandable folder row
- Preserve drag-to-reorder within a directory level
- New-file button becomes "New File…" (in current folder) and optionally
  "New Folder…"

Files to touch: `ui/file_tree.rs` (significant rewrite of row structure).

---

### 5. Project Templates

Templates are Typst starter files generated by the New Project wizard (§1).

Templates to ship:

**Blank**
- `main.typ` — minimal page setup, cursor ready

**Essay**
- `main.typ` — title, author, date, single body section, bibliography include
- `bibliography.bib` — empty BibTeX stub

**Journal / Thesis**
- `main.typ` — includes title page, each chapter, and bibliography
- `title.typ` — title page
- `ch01-introduction.typ` — chapter stub with heading
- `bibliography.bib` — empty BibTeX stub

**Theological Journal (specific to primary use case)**
- `main.typ` — includes front matter, articles, back matter
- `front-matter.typ` — journal title, volume, issue, editorial note stub
- `article-01.typ` — article stub (title, author, abstract, body)
- `bibliography.bib` — empty BibTeX stub

Templates live in `src/templates/` as Rust string constants or embedded files,
not on disk until generated.

Files to touch: new `templates.rs` module, called from `ui/new_project_dialog.rs`.

---

### 6. `#include` Insert Helper

Right-click a file in the file tree → "Insert `#include` at cursor".

- Inserts `#include "<relative-path-to-file>"` at the current cursor position in
  the active editor tab
- Path is relative to the current compilation root's directory
- Also add "Insert `#import`" for files that export functions/variables

Files to touch: `ui/file_tree.rs`, callback wiring through `ui/app_window.rs` to
`ui/editor_pane.rs`.

---

### 7. (Nice-to-have) Cross-Project Word Count

The word count button currently counts only the active tab's buffer.

- When a project has a root file with includes, count words across all included
  files (walk the include graph from ProjectModel)
- Show in the word count statistics popover as "Project total: N words / File: N words"

Files to touch: `ui/editor_pane.rs` (word count popover), `project_model.rs`.

---

### 8. (Nice-to-have) Cross-File Heading Outline

The document outline currently shows headings from the active tab only.

- When a root file is set and includes are resolved, show headings from all
  included files in document order
- Each outline row shows which file the heading is from (small secondary label)

Files to touch: `ui/sidebar.rs` or wherever the outline panel lives, `project_model.rs`.
